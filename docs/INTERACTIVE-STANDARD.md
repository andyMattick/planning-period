# The interactive assignment standard (owner, Nov 5, 2026)

Every interactive (virtual) assignment we make for a teacher meets this standard: interactive worksheets, interactive
notes and lessons, and anything built for a learning world. It does not apply to paper assignments. The owner wrote it
from interactive notes he has built elsewhere; the text below is his, with a rule id added to each line so checks and
reports can point at it. `checks/interactive-standard.mjs` tests every rule that code can test; the rest are checked by
independent reviewers (marked **review**).

## How a lesson is designed

- **L1** Lessons run in reverse: a hook, then labs where students discover the pattern, then the rule is named, then check questions, then the notes sheet.
- **L2** Each lesson covers one idea, with about 40 minutes of required work (35 to 45). Anything beyond that is clearly marked optional and doesn't block finishing.
- **L3** Each lesson uses at least 3 different mechanics, never the same one twice in a row. Examples are simulate, sort, build, predict-then-reveal, find-the-mistake and slider hunts.
- **L4** Each lesson has a hook with a story or contest, and the closing checkpoint is reframed each time rather than repeated.
- **L5** Include off-the-board activities when they teach better, each with a materials list, a place to enter the result, and a "simulate it for me" fallback.
- **L6** Every blank from your source worksheet appears as a fill-in somewhere, with a coverage check against an inventory of the blanks.
- **L7** Rule cards unlock only after the required labs above them.
- **L8** No lesson is ever locked unless you ask for locking in that request.

## Question rules

- **Q1** Every auto-checked question has a hint, a wrong-answer message that says why that choice is wrong, and an explanation shown after the student gets it right.
- **Q2** Answer order is shuffled by the engine at display time, with a fixed seed per lesson.
  - **Q2a** No run of 3 in a row.
  - **Q2b** No repeating cycle of 2 to 4.
  - **Q2c** No slot used much more than its share.
  - **Q2d** Two-option items are about half and half.
  - **Q2e** Saved data keeps the original option numbers, so old saves still work.
- **Q3** Answer length can't give it away.
  - **Q3a** The correct answer is the strictly longest in at most about 30% of items, and the strictly shortest in at most about 30%.
  - **Q3b** It is never the only option with a "because" reason, or the only one without.
  - **Q3c** No silly distractors, no lone exact number or hedge, no overused "all of the above", and no reuse of one wrong-answer pattern.
- **Q4** Typed answers accept equivalent forms: 0.125, .125, 1/8 and 12.5%, plus plurals, case, symbol-or-word forms and sensible rounding.
- **Q5** Free responses have a model answer and look-fors for the teacher only, never in the student files.
- **Q6** Explanations are written in plain student voice, with no AI tells like stacked triplets or "moreover".

## Notes page and student tools

- **N1** A cumulative, printable My notes page comes last in the navigation. It holds answers the student got right with their explanations, filled blanks, key ideas, free responses and the teacher-question answer. It never holds hints or model answers.
- **N2** Every page has a collapsible own-notes box, and a "Where I got stuck" list records every wrong answer tried.
- **N3** Students can add their own notes as they go.
- **N4** Print layout hides the sidebar and buttons and shows a Name/Date line to fill in by hand.

## Teacher questions and guess-and-click defenses

- **T1** There are two short answers per lesson (12 or more words, in context), then one teacher question per lesson. The question is stored only as ciphertext.
- **T2** It reaches students two ways every time: your private board page, and a code box on the student's page. Typing the code shows the question but never marks it done.
- **T3** Wrong multiple-choice picks stay marked, even after reload. Each miss adds a wait (5 seconds, up to 20), and after two misses the student writes one sentence on what they were thinking.
- **T4** The page is a pacing tool, not tamper-proof.

## Saving

- **S1** Autosave, autoload, a backup file, a save code, and a "Saved automatically at…" line.
- **S2** Storage keys, lesson ids and question ids stay fixed forever.
- **S3** Loaders merge over defaults and never clear anything.
- **S4** Notes keep their own copy of the text they were made from.
- **S5** Whenever an assignment changes, I check that old saved work still shows.

## Teacher copy

- **C1** Generated by script, never by hand, from the student file.
- **C2** Show ANSWERS / Show BLANK toggle (F2 only, never a letter key), highlighting the correct option by its original number.
- **C3** It is display-only except for Reset lesson.

## Checks before you see it

- **K1** A student-style QA gate runs first. It dumps what students actually see and checks answer positions and lengths. It recomputes every answer in code and clicks through at laptop and phone width, in a sandboxed frame. It also tests reload, backup and blocked storage.
- **K2** Independent reviewers check source fidelity, difficulty, timing, voice, math and answer patterns.
- **K3** A content review packet comes first if you want one: every problem and answer, sample students, judgment calls, and the multiple-choice audit.

## AP classes

- **A1** Every lesson gets a bell ringer: 3 to 5 multiple choice plus one FRQ, College Board level, about 10 minutes.
- **A2** Options are the same length, near-miss and misconception-based.
- **A3** The FRQ has a scoring guide, model response and typical wrong answers, kept on the teacher side only.
- **A4** CED codes go in the teacher key only. They aren't checked against the CED yet.

## Standing details

- **D1** A "Build N (what changed)" line shows at the bottom of each page.
- **D2** `href="#/..."` links get a document-level click handler so they work inside the viewer.
- **D3** The nickname-only and AI-disclaimer rules are hosting rules, so they are left out above.
